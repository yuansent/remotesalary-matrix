# 付费产品与商业验证标准 v1

这套标准首先用于约束当前项目。它能减少错误和夸大，不能保证赚钱。对“物超所值”的判断最终来自用户完成任务、比较替代方案、真实付款和退款/支持负担。

## 1. 五个独立阶段

1. **方向假设**：具体买家、触发场景、当前替代方案、未解决成本、为何愿意购买。必须写最可能失败的原因。竞品有收入只能证明有人付过类似的钱。
2. **交付质量**：承诺逐条对应实际交付；下载后从空白输入到结果走通；公式、边界、来源、格式和版本检查通过。AI 自测只能证明这部分。
3. **任务价值**：代表性用户在不接受作者逐步指导的情况下完成目标任务；记录输入、时间、错误、需要帮助的步骤、替代工具表现和愿付价格。AI 模拟不能充当真实用户。
4. **付费需求**：真实目标用户在透明披露的条件下实际支付；排除本人、关联人、测试单。记录合格访问量的分母及来源，不能把点击当需求。少数付款是信号，不是稳定市场证明。
5. **可持续收益**：跨多个观察周期记录净收入、退款、手续费、获客费用、维护和支持时间。只有人工负担持续较低才讨论“睡后收入”。

任何阶段未验证，报告必须停留在该阶段。不能通过前四项检查就写“盈利已验证”。

## 2. 商品必须先有可验收规格

每个版本建立 manifest：一个具体买家任务、明确输入/输出、适用和不适用范围、文件清单与 SHA256、营销承诺逐条映射、重大声明的来源记录、计算验证、用户任务记录、专业复核和批准记录。修改文件后旧哈希和批准失效。

- 文件存在不等于内容覆盖；25 国必须逐国有相应条目，不能按标题写 25。
- 每个会影响决策的数字/规则关联来源 URL、对应原文、适用对象、司法辖区、访问日期、规则生效期及复查触发条件。网页存在不代表支持该结论，日期刷新不代表复核。
- 没有来源的事实删除或明确标为假设。预算场景与事实数据分开。
- 法律合同、税务结论或合规保证必须经过适当辖区及专业能力的复核；免责声明不能代替正确性。无法承担专业复核时，应缩成信息整理工具，移除相应结论与条款承诺，并重新验收。
- 没有真实运行的更新机制，不能写实时/每周更新。没有实际机构授权，不能称官方；不能编造折扣原价、接受率、节省比例。

## 3. 计算与交付验收

检查实际下载的字节与交付哈希；干净环境解压/打开。电子表格以实际计算引擎重算，检查错误值和输入变化，不以“公式字符串存在”代替运行结果。

日数工具至少检查：同日、跨年、闰日、空值、反向日期、重叠区间、重复行、多个国家、国家筛选、日期窗口和行扩展。明确计入入境/离境日的约定，不能从天数直接推出合法/税务居民身份。预算工具必须使用用户输入的收入、单位与币种，区分月/年及税前/税后，解释税制简化的适用范围。

文档必须有填写指南、完整示例和使用边界。不能让用户默认声明不真实的工资、雇佣期限、附件、权利或法律结论。模板语言与国家定制程度必须与宣传一致。视觉 QA、拼写和自动检查通过后，仍需任务验收。

## 4. 最小商业实验：先声明再执行

下一轮只选一个买家、一个低风险任务、一个渠道。建议先研究 AICost 的“按真实工作负载比较供应商成本”任务：仍需核实是否有人需要，以及免费官方计算器能否已满足；这只是候选，不是已决定的新付费品。

执行前填写：目标人群/场景、替代方案、具体可证伪假设、价格、合格访问定义、渠道、观察窗口、现金预算上限、工时上限、成功/停止条件及授权范围。预算和阈值在看结果前由负责人确认，不由代理事后调整。不得以“再多做些页面”替代实验失败的结论。

初始可先完成 5 次独立代表用户任务观察（探索性，不具统计代表性），在实验计划中说明如何招募和避免熟人偏差。不要把这个数字当自动售卖许可。收款前仍需通过质量与复核门槛。没有渠道能触达买家，也是有效的负面发现。

每个周期记录：原始来源/查询时间、合格独立访问、机器人/本人/测试剔除、购买人数、实收、退款、费用、工具/投放支出、维护支持工时及样本局限。未知写 null，真实 0 需要可核对的完整窗口证据。净贡献=实收−退款−手续费−获客/交付/工具成本；另列工时及选定时薪的敏感性。盈亏平衡订单量=固定成本÷单单贡献，单单贡献≤0 时不能靠增加订单达到平衡。

停止：发现会误导决策的错误立即停止新销售；现金/时间触顶即暂停扩张；实际任务失败先修产品；有访问无付费检查人群/价值/价格；无合格访问只说明获客未验证。禁止把任何一种失败解释为“方向一定对，只要坚持”。

## 5. 重开与发布门禁

两个现有 SKU 的阻断项见本次审计。清空每个阻断项需要具体证据及负责人复核，不接受一句“已修复”。重新生成或改名商品也必须过同样门槛。

`04-pipeline/product_release_gate.py` 是只读证据完整性门禁：检查文件哈希、承诺/来源映射、必需复核与证据文件，以及明确人工批准。当前两个 manifest 应失败。它无法验证专家资质、研究真实性、来源对法律结论的充分性或真实需求，禁止将 PASS 写成商业成功。

技术上线前再核对线上 CTA、价格、实际下载、旧版本可访问情况和最终发布版本。人工批准必须指向 manifest 中的确切文件哈希；禁止恢复销售后补批准。每次报告分别写“已完成/验证方法/未验证/阻断/下一步”，并链接原始证据。

## 6. Hermes 交接纪律

先读项目 AGENTS、最新审计与真实状态，不沿用旧聊天里的乐观判断。每轮先复述当前阶段与最强反证，再提出最小下一步。所有新承诺先更新映射；涉及法律/税务不要用另一个模型的同意充当复核。未取得授权不得代发 X、邮件或私信。根目录不是 Git 仓库，交接必须包含根目录标准与证据，不能只拉取单个网站仓库。
